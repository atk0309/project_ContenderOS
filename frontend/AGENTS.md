# AGENTS.md — frontend (Next.js)

Nested guidance for the `frontend/` subtree. The root `AGENTS.md` holds the invariants and the
cross-service quality gate; this file holds only frontend toolchain + rules.

## Stack

Next.js (App Router) + React 19 + TypeScript (strict). Design tokens as CSS variables in
`src/app/globals.css`; the canonical Claude design is vendored in `docs/design/` and specced in
`docs/architecture/design-system.md`. Fonts via `next/font`. Lint/format `biome`, typecheck
`tsc --noEmit`, unit test `vitest`. Live-preview verification via Playwright MCP.

## Commands

| Purpose | Command |
|---|---|
| Install deps | `pnpm install` |
| Generate API types from backend OpenAPI | `pnpm gen:types` |
| Lint / format | `pnpm lint` / `pnpm format` |
| Typecheck | `pnpm typecheck` |
| Test | `pnpm test` |
| Frontend gate (what root gate runs) | `pnpm gen:types && pnpm lint && pnpm typecheck && pnpm test` |

## Rules

- **Types come from `src/lib/api/generated-types.ts`** (generated by `gen:types` from
  `frontend/openapi.json`). Never hand-write a CV/JobSpec/Review interface. The file is
  biome-ignored and committed; the gate fails if it drifts from the backend schema.
- **The renderer is the load-bearing surface.** `src/render/ResumeTemplate.tsx` is shared by the
  live preview AND the PDF (Playwright prints the hidden `/print/[cvId]` route). A change to it
  changes the exported document — treat it as a render-path change and verify preview == PDF
  (Playwright MCP). DOCX (`docx-mapper.ts`) and ats-text (`text-mapper.ts`) derive from the same
  `TailoredCV` + `template-tokens.ts`.
- The deterministic slop heuristics (`src/slop/heuristics.ts`) run **client-side on keystroke** —
  no network, no model. Flags anchor by stable id.
- Next.js holds **no business logic** — only UI + the three render routes (`app/api/render/*`).
  All AI/data/auth is the FastAPI backend, reached via `src/lib/api/client.ts` (credentials
  included). Provider keys never touch the client bundle.
- **The authed app shell lives in `src/app/(app)/`** — a route group wrapping the authed pages
  in one `AppShell` (left-rail nav) + `SessionProvider` (one `/auth/me` gate; consume via `useSession()`)
  + `ReadinessProvider` (`useAiReadiness()`, the AI-tailoring readiness signal). `/sign-in` and
  `/print/[cvId]` stay **outside** the group so the render path is shell-free (invariant 3). Route groups
  are URL-transparent — moving a page under `(app)/` changes no URL.
- **Shared UI primitives live in `src/ui/`** (`Button`/`buttonStyle`, `Card`/`cardStyle`, `PageHeader`,
  `Field`/`inputStyle`, `Banner`, `tagStyle`) — reuse them for app chrome instead of re-declaring inline
  style objects per page. Presentational, chrome tokens only; **never import `src/ui` from
  `src/render/**`** or the print route. (All five authed screens source their button/card/banner/tag
  styles from `src/ui`; genuinely page-specific styles stay local — e.g. ingest's 44px-tap-target
  buttons + 16px iOS inputs are intentional mobile variants, not drift.)
- **Design fidelity is token-enforced.** App chrome consumes design tokens only — **no ad-hoc colour
  literals** in `src/app`/`src/ui`. The machine guard in `scripts/check-invariants.mjs` fails the gate
  on `#hex`/`rgb()`/`hsl()`/`oklch()` there (allowlist: neutral black shadows); `/print` +
  `src/render/template-tokens.ts` are render path and keep concrete colours.
  Agent identity (name/glyph/colour/role) + Gatekeeper decision colours come from the single source
  `src/ui/colors.ts` — never re-declare them. Canonical design + the per-screen fidelity rubric:
  `docs/architecture/design-system.md` + `docs/design/`.
- Match the design: dark-first, both themes from one token set, visible focus, reduced-motion,
  Tracker + review notes usable on iPhone width.
